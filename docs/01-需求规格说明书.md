# 01 需求规格说明书

## 1. 背景与目标

### 1.1 背景

在微服务与分布式系统中，单点故障或依赖方性能劣化会沿调用链快速扩散（雪崩效应）。熔断降级是服务治理的三板斧（熔断、降级、限流）之一：当被依赖的服务持续出错时，本地快速失败并返回降级结果，避免调用方线程被阻塞、资源被耗尽。

本项目基于原始需求提示词扩写：

> **熔断降级组件**：用 Go 实现熔断器库，维护三种状态机，基于滑动窗口统计错误率，支持半开探测与并发隔离。

### 1.2 目标

- 提供一个**可复用的熔断器库**（`breaker` 包），语义与工业界主流实现（Netflix Hystrix、Sentinel、Go-resilience）对齐但保持精简。
- 配套**接入层**（HTTP 中间件）、**服务层**（监控/管理 API）与**展示层**（Web Dashboard），形成开箱即用的完整演示闭环。
- 满足规模约束：Go 代码（不含测试）2,000 ~ 2,200 行，Go 代码文件 21 ~ 24 个。

### 1.3 术语表

| 术语 | 含义 |
| --- | --- |
| Resource | 被保护的调用目标标识（如 `getUser`、`payOrder`） |
| Breaker | 某资源对应的熔断器实例，持有独立状态机、滑动窗口与信号量 |
| Closed | 关闭态：正常放行请求并统计指标 |
| Open | 打开态：立即拒绝请求，进入冷却期 |
| Half-Open | 半开态：放行受限探测请求，验证上游是否恢复 |
| Sliding Window | 滑动窗口：按时间桶聚合的最近 N 秒统计 |
| Error Rate | 错误率：窗口内失败数 / 总请求数 |
| Sleep Window | 冷却时间：Open 态持续时长，到期后进入 Half-Open |
| Probe | 半开探测请求，用于试探上游恢复情况 |
| Semaphore | 信号量：并发隔离的核心原语 |
| Fallback | 降级执行：拒绝或异常时返回兜底结果 |

## 2. 功能需求

### FR-01 三态熔断状态机

- 每个熔断器维护 **Closed / Open / Half-Open** 三态。
- 状态迁移规则（详见 03 文档的状态转换表）：
  - `Closed → Open`：窗口内请求数 ≥ 最小请求数 且 错误率 ≥ 错误率阈值。
  - `Open → Half-Open`：冷却时间到期后自动进入。
  - `Half-Open → Closed`：探测请求连续成功数达到阈值。
  - `Half-Open → Open`：任一探测请求失败。
- 状态变更需触发事件并记录时间点，供监控与前端展示。

### FR-02 基于滑动窗口的错误率统计

- 以**固定时长的桶（Bucket）**组织统计：默认每桶 1 秒，窗口 10 个桶（可配置）。
- 每个桶独立记录：成功数、失败数（含错误分类：调用错误 / 超时 / 并发拒绝 / 熔断拒绝）。
- 窗口随当前时间**滑动**：过期桶被淘汰，仅统计最近 N 秒。
- 提供接口查询：窗口请求总数、成功数、失败数、错误率、并发拒绝数、熔断拒绝数。
- 滑动窗口需并发安全，并允许手动重置。

### FR-03 半开探测

- Open 态冷却到期后，熔断器进入 Half-Open，**只放行有限数量的探测请求**（默认 1，可配置）。
- 探测请求执行结果：
  - 连续成功达到阈值（默认 1 次）→ 回到 Closed，并清空窗口统计。
  - 任一次失败 → 立即回到 Open，冷却期重新计时。
- 探测期间其余请求按熔断拒绝处理（快速失败）。
- 记录探测次数与探测结果，供前端展示恢复过程。

### FR-04 并发隔离

- 每个熔断器持有**信号量（Semaphore）**，默认最大并发 100（可配置）。
- 请求进入执行前需先获取许可：
  - 获取成功 → 执行真实调用，结束后释放。
  - 获取失败或等待超时（默认 0，即不等待）→ 快速失败，计入"并发拒绝"。
- 并发隔离与熔断判定**先后协作**：先判状态（Open 直接拒绝），再判并发（超限拒绝），最后执行调用。

### FR-05 多级降级策略

- 触发降级的四种场景：
  1. 熔断拒绝（Open / Half-Open 非探测请求）。
  2. 并发隔离拒绝（信号量不可用）。
  3. 调用超时（超过配置的超时时间）。
  4. 调用返回错误（业务错误）。
- 降级方式（可配置优先级）：
  - `FallbackFunc`：用户自定义兜底函数（推荐，返回降级结果与降级原因）。
  - `DefaultValue`：返回默认值。
  - `ReturnErr`：直接返回熔断错误，不降级。
- 降级执行本身失败时，返回原始错误并记录事件。

### FR-06 熔断器注册中心（Registry）

- 提供全局注册中心，按资源名管理熔断器实例（`GetOrCreate` 语义）。
- 支持：注册、查询、列表、删除、批量重置、批量导出配置。
- 同一资源名全局唯一实例，避免重复统计。

### FR-07 事件监听

- 定义事件类型：
  - `StateChanged`：状态迁移（含 from/to/时间/原因）。
  - `RequestResult`：单次请求结果（默认关闭采样，可开启）。
  - `BreakerCreated` / `BreakerRemoved`：实例生命周期。
  - `MetricSnapshot`：周期指标快照（默认每 5 秒）。
- 支持注册多个监听器（回调函数式），监听器异常不影响主流程。
- 内部事件总线采用无阻塞扇出（goroutine + channel，或同步调用，设计见 03 文档）。

### FR-08 指标采集

- 每个熔断器维护累计指标：请求总数、成功、失败、超时、并发拒绝、熔断拒绝、探测成功、探测失败、错误率、P50/P95 耗时（近似）、当前并发。
- 指标通过 `Snapshot()` 方法原子导出，供监控 API 与 Dashboard 使用。
- 指标窗口与累计计数并存：窗口指标用于熔断判定，累计计数用于展示。

### FR-09 动态配置

- 配置项（均可运行时更新）：错误率阈值、最小请求数、窗口大小、桶时长、冷却时间、半开探测并发、连续成功阈值、最大并发、调用超时、降级策略。
- 通过 `UpdateConfig(cfg)` 原子更新；注册中心支持批量更新。
- 配置更新触发 `ConfigChanged` 事件。

### FR-10 HTTP 中间件

- 提供 `middleware.New(registry, options)` 生成标准 `net/http` 中间件。
- 中间件职责：按路由模式提取资源名 → 执行熔断/并发判定 → 调用下游 Handler → 分类记录结果（2xx/4xx/5xx/超时）→ 触发降级。
- 支持中间件级配置：资源名提取函数、超时、降级响应内容、是否记录请求体。
- 兼容 `http.Handler` 链式使用。

### FR-11 监控 API

- `GET /api/breakers`：熔断器列表（名称、状态、错误率、请求量）。
- `GET /api/breakers/{name}`：单实例详情（含窗口桶明细、指标、配置）。
- `GET /api/metrics`：全局聚合指标。
- `GET /api/events?since=`：最近事件流（供前端轮询）。
- 全部返回 JSON；服务优雅关闭。

### FR-12 管理 API

- `PUT /api/breakers/{name}/config`：动态更新配置。
- `POST /api/breakers/{name}/reset`：重置窗口与计数。
- `POST /api/breakers/{name}/state`：手动强制切换状态（演示/测试用）。
- `POST /api/breakers/{name}/probe`：手动触发一次半开探测。
- 管理操作均记录事件。

### FR-13 Web Dashboard（简单前端）

- 单页应用，原生 HTML/CSS/JS，无构建步骤。
- 功能模块：
  1. 熔断器总览卡片：状态徽章、错误率、请求量、并发占用。
  2. 单实例详情：指标数字、滑动窗口柱状图（成功/失败/拒绝）、状态迁移时间线。
  3. 演示控制台：注入失败流量、切换状态、重置、调阈值。
  4. 全局指标栏：总请求、总拒绝、整体错误率。
- 数据通过 fetch 轮询监控/管理 API（默认 2 秒）。

### FR-14 示例演示应用

- `cmd/demo`：演示服务，包含：
  1. 业务路由（模拟 `getUser` / `payOrder` / `searchGoods` 三个资源）。
  2. 模拟上游（可配置失败率、延迟）。
  3. 启动时注册 3 个熔断器并挂载 Dashboard 静态资源。
- 演示脚本建议（文档 07 提供操作步骤）。

## 4. 业务逻辑详述（核心场景）

### 4.1 请求执行主流程

```
请求进入
  │
  ├─ 1. 状态检查：State == Open 且非探测期？
  │      是 → 熔断拒绝（计数 RejectedByBreaker）→ 执行降级 → 返回
  │      否 ↓
  ├─ 2. 并发隔离：尝试获取信号量（可配等待超时）
  │      失败 → 并发拒绝（计数 RejectedByConcurrency）→ 执行降级 → 返回
  │      成功 ↓
  ├─ 3. 执行调用（可配超时）
  │      成功 → 记录成功 → 释放信号量
  │      失败 → 记录失败 → 释放信号量
  │      超时 → 记录超时（计入失败）→ 释放信号量 → 执行降级
  │      异常 panic → recover，记录失败 → 释放信号量 → 执行降级
  └─ 4. 触发 RequestResult 事件（若开启采样）与窗口指标更新
```

### 4.2 熔断判定（Closed 态每请求后）

```
窗口统计更新后：
  若 窗口请求总数 ≥ MinRequests
  且 窗口错误率 ≥ ErrorThreshold
  → 状态机 Closed → Open（记录熔断时间 = 当前时间 + SleepWindow）
```

### 4.3 冷却与半开探测（Open 态）

```
每请求进入时检查：
  若 当前时间 ≥ 熔断时间（冷却到期）：
    状态机 Open → Half-Open（重置探测计数）
    放行 ≤ ProbeCount 个探测请求
  否则：
    熔断拒绝

Half-Open 内探测请求结果：
  成功：连续成功计数 +1；若 ≥ SuccessThreshold → 状态机 Half-Open → Closed（清空窗口）
  失败：状态机 Half-Open → Open（重新记录熔断时间）
  其余并发进入的请求（超出探测并发）：熔断拒绝
```

### 4.4 降级执行

```
降级入口（拒绝 / 超时 / 错误 三类原因）：
  1. 若配置 FallbackFunc → 执行之；成功返回其结果；失败返回原始错误
  2. 否则若配置 DefaultValue → 返回默认值 + 降级标记
  3. 否则 → 返回对应错误（ErrBreakerOpen / ErrConcurrencyLimit / ErrTimeout / ErrCallFailed）
```

### 4.5 动态配置热更新

```
更新流程：解析新配置 → 校验合法性（阈值 ∈ [0,1]、窗口 ≥ 1 等）→ 原子替换熔断器配置快照 → 触发 ConfigChanged 事件
影响：新请求按新配置判定；滑动窗口尺寸变化时重建窗口（重置统计）
```

### 4.6 事件流与监控闭环

```
熔断器（状态/指标/配置变更）→ 事件总线 → 监听器（默认内置：环形缓冲区，最多保留 500 条）
                                          ↓
监控 API /api/events ──轮询──→ Web Dashboard 时间线
```
