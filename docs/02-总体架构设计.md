# 02 总体架构设计

## 1. 架构总览

系统采用**分层架构**，自下而上分为五层：

```
┌────────────────────────────────────────────────────────────────┐
│  展示层（前端）                                                │
│  web/index.html + style.css + app.js  （Dashboard 单页）        │
└──────────────────────────────┬─────────────────────────────────┘
                               │ fetch / 轮询（JSON）
┌──────────────────────────────▼─────────────────────────────────┐
│  服务层（监控/管理 API）                                        │
│  server/：server.go、handlers.go、metrics.go、api_models.go     │
│  路由：/api/breakers、/api/metrics、/api/events、/api/demo/*    │
└──────────────────────────────┬─────────────────────────────────┘
                               │ 调用
┌──────────────────────────────▼─────────────────────────────────┐
│  集成层（HTTP 中间件）                                          │
│  middleware/：middleware.go、http.go                            │
│  将请求分类、执行熔断判定、记录结果、触发降级                    │
└──────────────────────────────┬─────────────────────────────────┘
                               │ 调用
┌──────────────────────────────▼─────────────────────────────────┐
│  核心库（熔断器库）                                             │
│  breaker/：state / sliding_window / semaphore / fallback /      │
│            metrics / event / registry / config ...              │
└──────────────────────────────┬─────────────────────────────────┘
                               │ 调用
┌──────────────────────────────▼─────────────────────────────────┐
│  示例层（演示应用）                                             │
│  cmd/demo/：main.go、mock.go（业务路由 + 模拟上游）             │
└─────────────────────────────────────────────────────────────────┘
```

**依赖方向**：上层依赖下层，核心库 `breaker` 不依赖任何上层与第三方包（仅标准库）。

## 2. 分层职责

| 层 | 包 | 职责 | 对外依赖 |
| --- | --- | --- | --- |
| 核心库 | `breaker` | 熔断状态机、滑动窗口、并发隔离、降级、事件、指标、注册中心 | 仅标准库 |
| 集成层 | `middleware` | 适配 `net/http`，把 HTTP 请求接入熔断器 | `breaker` |
| 服务层 | `server` | 监控/管理 REST API、事件查询、静态资源托管 | `breaker`、`middleware` |
| 展示层 | `web` | Dashboard 页面与交互逻辑 | 服务层 API |
| 示例层 | `cmd/demo` | 演示服务装配、模拟上游、演示路由 | 全部上层 |

## 3. 模块设计

### 3.1 核心库 breaker（14 个文件）

| 文件 | 职责 | 关键类型 |
| --- | --- | --- |
| `breaker.go` | 熔断器主类型：请求入口 `Execute`、状态检查、探测调度、配置快照 | `Breaker` |
| `state.go` | 状态枚举、状态命名、迁移判定与迁移执行 | `State`、`transition` |
| `config.go` | 配置结构、默认值、合法性校验、合并 | `Config` |
| `options.go` | 构造选项（函数式 Option）、注册中心选项 | `Option` |
| `errors.go` | 错误定义与错误分类辅助 | `ErrBreakerOpen` 等 |
| `bucket.go` | 时间桶：计数结构、快照 | `Bucket` |
| `window.go` | 滑动窗口接口定义 | `Window` |
| `sliding_window.go` | 滑动窗口实现：桶轮换、聚合、重置 | `slidingWindow` |
| `semaphore.go` | 并发隔离信号量：获取/释放/尝试 | `Semaphore` |
| `result.go` | 请求结果分类与记录 | `Result`、`ResultType` |
| `metrics.go` | 累计指标、耗时分布、快照导出 | `Metrics`、`Snapshot` |
| `event.go` | 事件类型、事件总线、监听器管理 | `Event`、`EventBus` |
| `registry.go` | 注册中心：GetOrCreate、列表、批量操作 | `Registry` |
| `fallback.go` | 降级策略类型与执行器 | `Fallback`、`FallbackType` |

### 3.2 注册中心与实例生命周期

```
Registry（全局单例，也可独立创建）
  │  map[string]*Breaker  +  RWMutex
  ├─ Get(name)                → 已存在则返回
  ├─ GetOrCreate(name, opts)  → 不存在则创建并注册（触发 BreakerCreated 事件）
  ├─ List()                   → 全部实例快照
  ├─ Remove(name)             → 删除（触发 BreakerRemoved 事件）
  ├─ ResetAll()               → 全部重置
  └─ UpdateConfigAll(cfg)     → 批量动态配置
```

### 3.3 事件总线

```
EventBus（每实例一个 + 注册中心一个，可共用）
  │  监听器表 map[EventType][]Listener（RWMutex）
  ├─ Subscribe(fn)          → 订阅全部事件
  ├─ SubscribeType(t, fn)   → 按类型订阅
  ├─ Publish(ev)            → 同步扇出（监听器内建环形缓冲区，默认保留 500 条）
  └─ Recent(n)              → 最近 n 条事件（供 /api/events 查询）
设计决策：Publish 采用同步调用，保证事件顺序与"先变更后可见"；
监听器自身须快速返回，内置缓冲监听器通过独立 goroutine 写入环形缓冲区。
```

### 3.4 服务层 API 装配

```
server.New(registry, opts) → *Server
  ├─ 路由注册（见 04 文档 §4）
  ├─ 静态资源：/ → web/index.html（embed 打包，保持单二进制）
  └─ Run(addr) → 优雅启停（context + signal）
```

### 3.5 示例应用 cmd/demo

```
main.go：
  1. 构建 Registry，注册 3 个资源：getUser / payOrder / searchGoods（不同阈值演示不同状态）
  2. 装配 server，挂载静态 Dashboard
  3. 注册业务 Handler（经 middleware 包裹）
  4. 启动 HTTP 服务（默认 :8080）
mock.go：
  1. 模拟上游：按查询参数 failRate / latencyMs 返回成功或 500
  2. 提供故障注入接口 /api/demo/simulate（控制某资源的失败率与持续时间）
```

## 4. 关键数据流

### 4.1 请求处理数据流（含中间件）

```
HTTP 请求
  → middleware.Handler（提取资源名）
      → breaker.Execute(ctx, resource, fn, opts)
          → 状态检查（Open?）
          → 信号量获取（超限?）
          → 执行 fn（带超时）
          → 结果分类（成功/失败/超时）
          → 窗口与指标更新
          → 状态机迁移判定
      → 降级执行（如被拒/失败）
  → HTTP 响应（正常或降级内容，含 X-Breaker-State 响应头）
```

### 4.2 监控数据流

```
Breaker 指标/窗口/状态
  → Snapshot()（原子快照）
  → server/handlers.go（JSON 序列化）
  → 前端 app.js（每 2 秒轮询渲染）
```

### 4.3 演示数据流

```
Dashboard 演示控制台
  → POST /api/demo/simulate（failRate、seconds）
  → cmd/demo/mock.go 注入故障（失败率、延迟）
  → 前端业务请求经中间件进入熔断器
  → Dashboard 观察到 Closed → Open → Half-Open → Closed 全流程
```

## 5. 并发模型

| 结构 | 并发策略 |
| --- | --- |
| `Breaker` 状态字段 | `atomic.Int32`（状态枚举原子读写） |
| 滑动窗口桶 | 桶内计数用 `atomic.Int64`；桶轮换加短临界区锁 |
| 信号量 | `chan struct{}` 实现，容量 = 最大并发 |
| 注册中心 map | `sync.RWMutex` |
| 事件总线 | `sync.RWMutex` + 回调式 |
| 配置快照 | `atomic.Pointer[Config]` 原子替换，无锁读 |
| 指标 | 请求路径原子累加，快照时加锁拷贝 |

**原则**：请求热路径尽量无锁（原子操作 + 快照指针），写多读少的结构用 RWMutex。

## 7. 关键设计决策（ADR 摘要）

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| ADR-01 | 滑动窗口采用"固定桶 + 滑动聚合"，而非环形缓冲精确滑动 | 实现简单、并发安全、误差 ≤ 1 桶，满足熔断场景 |
| ADR-02 | 信号量隔离采用 `chan struct{}` | 标准库原语，天然支持 TryAcquire 语义 |
| ADR-03 | 事件总线同步扇出 | 保证事件因果顺序，代价是监听器必须快速返回 |
| ADR-04 | 配置用 `atomic.Pointer` 快照 | 热路径无锁读，更新原子生效 |
| ADR-05 | 前端不引入框架与构建链 | 满足"简单前端"，原生 fetch + DOM 渲染即可 |
| ADR-06 | 静态资源用 `embed` 打包 | 单二进制部署，演示零依赖 |
| ADR-07 | 中间件只适配 `net/http` | 目标明确、演示闭环自洽，避免依赖第三方路由 |
| ADR-08 | 状态机迁移集中在 `state.go` | 单一变更点，便于单元测试全覆盖 |
