# 03 核心算法设计

本文档定义熔断器的全部核心算法：状态机、滑动窗口、半开探测、并发隔离、降级策略、事件与指标。实现阶段按本设计编码，单元测试用例见文档 07。

## 1. 状态机总览

```
                 错误率 ≥ 阈值 且 请求数 ≥ 最小请求数
   ┌─────────┐ ─────────────────────────────────────────▶ ┌─────────┐
   │ Closed  │                                             │  Open   │
   │  关闭   │ ◀─────────────────────────────────────────  │  打开   │
   └─────────┘   连续成功 ≥ 探测成功阈值（清空窗口）        └─────────┘
        ▲                                                       │
        │                ┌──────────────┐                       │ 冷却到期
        │                │  Half-Open   │ ◀─────────────────────┘
        └────────────────│    半开      │
           探测成功       └──────────────┘
           达到阈值            │
                              ▼
                    任一次探测失败 → 回到 Open（重新计时）
```

| 状态 | 含义 | 请求行为 |
| --- | --- | --- |
| Closed | 正常 | 全部放行，统计错误率，达到阈值即熔断 |
| Open | 熔断 | 拒绝全部请求（快速失败），冷却期 SleepWindow 后进入 Half-Open |
| Half-Open | 探测 | 仅放行 ≤ ProbeCount 个探测请求，其余拒绝；根据探测结果迁移 |

## 2. 状态转换表（完整定义）

| 迁移 | 触发条件 | 迁移动作 |
| --- | --- | --- |
| Closed → Open | 窗口内 `Total ≥ MinRequests` 且 `ErrorRate ≥ ErrorThreshold` | 记录 `openedAt = now`，`openUntil = now + SleepWindow`；重置探测计数；触发 StateChanged 事件 |
| Open → Half-Open | 当前请求到达且 `now ≥ openUntil` | 重置探测计数 `probeSuccess = 0`；触发 StateChanged 事件 |
| Half-Open → Closed | 探测请求成功且 `probeSuccess + 1 ≥ SuccessThreshold` | 重置滑动窗口与计数；触发 StateChanged 事件 |
| Half-Open → Open | 任一探测请求失败（调用失败/超时） | 记录 `openUntil = now + SleepWindow`；触发 StateChanged 事件 |
| Closed/Open/Half-Open → 任意 | 管理接口手动强制切换 | 按目标状态初始化（进入 Open 时设置 openUntil；进入 Closed 时清空窗口）；触发 StateChanged 事件 |

**边界规则**：
- 错误率计算分母为 0 时错误率视为 0。
- `MinRequests = 0` 表示不要求最小请求数（谨慎使用）。
- 半开期间窗口统计继续累计但不参与熔断判定（判定只在 Closed 态进行）。

## 3. 滑动窗口算法

### 3.1 数据结构

```
滑动窗口（每 Breaker 一个）
├─ bucketDuration: 1s（默认，可配置）
├─ windowSize:     10 个桶（默认，可配置，即窗口 10 秒）
├─ buckets:        [windowSize]Bucket（环形数组，逻辑上按时间排列）
│    Bucket
│    ├─ StartAt     int64  桶起始时间戳（UnixNano）
│    ├─ Succeeded   atomic.Int64
│    ├─ Failed      atomic.Int64        // 调用错误
│    ├─ Timeout     atomic.Int64        // 超时（同时计入 Failed 口径）
│    ├─ RejectedC   atomic.Int64        // 并发隔离拒绝
│    └─ RejectedB   atomic.Int64        // 熔断拒绝
└─ currentIdx      int     当前桶下标
```

> 口径约定：`ErrorRate = (Failed + Timeout) / (Succeeded + Failed + Timeout)`，拒绝类计数不进入错误率分母（它们本就不该被计入调用质量）。

### 3.2 写入（每请求后调用）

```
record(resultType):
  1. now = time.Now().UnixNano()
  2. idx = now / bucketDuration % windowSize  —— 目标桶
  3. 若 target.StartAt 与当前桶不一致 → 执行桶轮换：
       for each 被跳过的桶：重置（StartAt 置空、计数清零）
       将目标桶 StartAt 对齐到 now 所在槽位
  4. 按 resultType 对目标桶对应计数器原子 +1
```

桶轮换采用"惰性重置"：只在写入时对路径上的过期桶清零，读取时通过 `StartAt` 判断桶是否在窗口内。

### 3.3 读取（聚合快照）

```
snapshot():
  now = time.Now()
  遍历全部桶：
    若桶 StartAt 非空 且 now - StartAt < windowSize × bucketDuration
    → 计入聚合（Succeeded/Failed/Timeout/RejectedC/RejectedB）
  输出：Total、Succeeded、Failed、Timeout、RejectedC、RejectedB、ErrorRate
```

读取不加锁：计数器为原子值，StartAt 读取可能短暂不一致，但误差在一个桶内，且并发安全（`-race` 通过）。

### 3.4 复杂度与正确性

- 写入 O(桶数) 最坏（轮换路径），均摊 O(1)；读取 O(桶数) = O(10)。
- 精确滑动窗口的误差上界为一个桶时长（1s），对熔断场景可接受。
- 重置（管理接口）：清空全部桶计数与 StartAt。

## 4. 半开探测算法

```
字段：probeCount（int，当前已放行探测数）
      probeSuccess（int，当前连续成功探测数）

进入 Half-Open 时：probeCount = 0，probeSuccess = 0

请求进入时的判定：
  if state == Half-Open:
      if probeCount < ProbeCount（默认 1）:
          probeCount++
          放行（标记为探测请求，探测期间不再取信号量，避免自锁）
      else:
          熔断拒绝

探测请求结束时：
  成功 → probeSuccess++
         if probeSuccess ≥ SuccessThreshold（默认 1）→ 迁移到 Closed，清空窗口
  失败/超时 → 迁移到 Open（openUntil = now + SleepWindow）
```

**要点**：
- 探测请求跳过信号量获取，避免"信号量被常规请求占满导致探测永远无法执行"的自锁问题。
- 探测并发上限 = ProbeCount；超过部分一律熔断拒绝。
- 探测结果单独计数（Metrics.ProbeSuccess / ProbeFailed），不进入常规失败计数。

## 5. 并发隔离（信号量）

### 5.1 数据结构与操作

```
Semaphore:
  ch  chan struct{}   // 容量 = MaxConcurrency（默认 100）
  n   atomic.Int64    // 当前占用

Acquire(timeout):
  if timeout <= 0:
      select { case ch <- struct{}{}: return true
               default: return false }           // 不等待
  else:
      带 time.After(timeout) 的 select 版本
Release(): <-ch; n--（调用方保证成对出现）
TryAcquire(): Acquire(0)
```

### 5.2 与熔断的协作顺序

```
1. 状态检查（Open / Half-Open 非探测）→ 拒绝（RejectedB）
2. 信号量获取 → 失败拒绝（RejectedC）
3. 执行调用（带超时）
4. 释放信号量（defer 保证，panic 场景 recover 后同样释放）
```

### 5.3 超时隔离

- 调用超时由 `context.WithTimeout` 实现（默认 3s，可配置）。
- 超时计入 `Timeout` 与失败口径，并触发降级。
- 上游返回后若已超时，结果丢弃（通过 select 竞态保证）。

## 6. 降级策略

### 6.1 触发分类

| 分类 | 触发点 | 结果类型 |
| --- | --- | --- |
| 熔断降级 | 状态 Open / Half-Open 拒绝 | RejectedByBreaker |
| 并发降级 | 信号量获取失败 | RejectedByConcurrency |
| 超时降级 | 调用超时 | Timeout |
| 失败降级 | 调用返回错误 | Failed |

### 6.2 策略优先级

```
FallbackFunc 已配置  → 执行 FallbackFunc(reason, result)
否则 DefaultValue 已配置 → 返回 DefaultValue（带降级标记）
否则 → 返回对应错误（ErrBreakerOpen / ErrConcurrencyLimit / ErrTimeout / ErrCallFailed）
```

### 6.3 FallbackFunc 契约

```go
type FallbackFunc func(reason Reason, result *Result) (interface{}, error)
// reason ∈ {ReasonBreakerOpen, ReasonConcurrencyLimit, ReasonTimeout, ReasonCallFailed}
// 返回降级结果；返回 error 时，该错误将向上传播
```

- FallbackFunc 执行 panic 时 recover 并返回原始拒绝错误。
- 降级执行不计入失败统计（避免降级失败引发二次熔断）。

## 7. 事件模型

### 7.1 事件类型

```go
type EventType int
const (
    EventStateChanged  EventType = iota // 状态迁移
    EventRequestResult                  // 单请求结果（默认关闭，采样开启时发布）
    EventBreakerCreated                 // 实例创建
    EventBreakerRemoved                 // 实例删除
    EventConfigChanged                  // 配置更新
    EventMetricSnapshot                 // 周期指标快照（默认 5s）
)
```

### 7.2 事件结构

```go
type Event struct {
    Type      EventType
    Resource  string
    Time      time.Time
    Data      interface{}   // 依类型而定：StatePayload / ResultPayload / SnapshotPayload 等
}
```

### 7.3 发布与订阅

- `Subscribe(listener func(Event))` / `SubscribeType(t, fn)`。
- Publish 同步扇出；内置 `BufferListener` 通过 channel + goroutine 写入 500 条环形缓冲，供 `/api/events` 查询。
- 监听器 panic 由发布方 recover，不影响请求主流程。

## 8. 指标模型

### 8.1 指标项（累计，从实例创建起）

| 指标 | 说明 |
| --- | --- |
| TotalRequests | 请求总数（含被拒） |
| Succeeded | 成功 |
| Failed | 调用失败 |
| Timeouts | 超时 |
| RejectedByBreaker | 熔断拒绝 |
| RejectedByConcurrency | 并发拒绝 |
| ProbeSuccess / ProbeFailed | 探测成功 / 失败 |
| InFlight | 当前并发占用 |
| AvgLatencyMs / P95LatencyMs | 平均 / P95 耗时（近似：滑动直方图，桶粒度 10ms，128 桶） |
| State | 当前状态 |
| StateChangedAt | 最近一次状态变更时间 |

### 8.2 快照导出

```go
type Snapshot struct {
    Resource string
    State    State
    Window   WindowSnapshot   // 窗口聚合（含桶明细）
    Metrics  MetricsSnapshot  // 累计指标
    Config   Config           // 当前生效配置
    OpenedAt time.Time        // 最近熔断时间
}
```

- 请求路径只做原子累加；`Snapshot()` 时加锁拷贝，保证一致性。
- P95 使用固定桶直方图近似，避免精确排序开销。

## 9. 伪代码：Execute 全流程

```
func (b *Breaker) Execute(ctx, fn) (interface{}, error):
    st := b.state.Load()
    now := time.Now()

    // 1. 状态与冷却处理
    if st == Open:
        if now >= b.openUntil.Load():
            b.transition(Open → Half-Open)        // 重置探测计数
            st = HalfOpen
        else:
            b.window.Record(RejectedB); b.metrics.Inc(RejectedByBreaker)
            return b.degrade(ReasonBreakerOpen)

    // 2. 半开探测调度
    probing := false
    if st == HalfOpen:
        if b.tryTakeProbe():                       // probeCount < ProbeCount
            probing = true
        else:
            b.window.Record(RejectedB); ...
            return b.degrade(ReasonBreakerOpen)

    // 3. 并发隔离（探测请求跳过）
    if !probing:
        if !b.sem.Acquire(b.cfg().AcquireTimeout):
            b.window.Record(RejectedC); ...
            return b.degrade(ReasonConcurrencyLimit)
        defer b.sem.Release()

    // 4. 执行调用（超时控制）
    res, err := b.runWithTimeout(ctx, fn)
    if err 为超时:
        b.record(Timeout, probing); return b.degrade(ReasonTimeout)
    if err != nil:
        b.record(Failed, probing)
        if probing: b.transition(HalfOpen → Open)
        else: b.maybeOpen()                        // Closed 态熔断判定
        return b.degrade(ReasonCallFailed)

    // 5. 成功
    b.record(Succeeded, probing)
    if probing:
        if b.probeSuccess+1 >= b.cfg().SuccessThreshold:
            b.transition(HalfOpen → Closed)        // 清空窗口
    return res, nil
```

## 10. 复杂度汇总

| 操作 | 复杂度 | 锁 |
| --- | --- | --- |
| 状态读取 | O(1) | 原子 |
| 窗口写入 | O(桶数) 最坏，均摊 O(1) | 原子 + 短临界区 |
| 窗口快照 | O(桶数) | 无锁（原子读） |
| 信号量获取 | O(1) | channel |
| 指标累加 | O(1) | 原子 |
| 事件发布 | O(监听器数) | RWMutex |
